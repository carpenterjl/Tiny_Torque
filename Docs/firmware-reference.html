Controller Firmware Reference

The complete contract between the simulator host and a controller DLL: every callable function, every sensor, its data layout, extraction code, and worked firmware examples. Written for the engineer sitting down to make a car drive itself.

ABI v6 control loop 100 Hz sensor types 12 plain C · no allocation across the boundary
data into firmware — sensors, CtrlInputs data out of firmware — actuators, CtrlOutputs

§1System overview

Your firmware is a native DLL. The simulator loads it, describes the car to it once, then calls it 100 times a second with fresh sensor data and applies whatever actuator commands it writes back.

Two headers define everything:

HeaderRoleYou edit it?
controller_api.hThe raw ABI — structs, sensor type tags, the exports your DLL must (and may) provide. Fixed plain-C layout, stable across compilers, marshalled to C# blittable structs on the host side.Never
tt_controller.hHeader-only helper library on top of the ABI: manifest parsing, named sensor reads, drive/steer/brake helpers, a PID, a frame-buffering camera ring. Every function is static inline — include it and go.Rarely (shared by every UserScripts/ folder)

1.1What you can build with it

Everything below is demonstrated with real code in §7:

Design rule the whole ABI follows

"Missing" never looks like a plausible reading. A ToF with no hit reports range_max, not 0. An empty RF slot reports id −1 at −100 dBm. Helper functions take a fallback argument and return it for any absent sensor. Firmware that reads garbage and drives into a wall is the failure mode this is built against.

§2Lifecycle exports

Six exports. Four are required; two are optional and change nothing if absent.

ExportSignatureReq.When called / contract
ctrl_init int ctrl_init(float control_rate_hz) REQ Once, after the car is built. control_rate_hz is the tick rate (typ. 100). Return 0 for success. Initialize all static state here — the DLL is torn down and rebuilt on every Build & Reload.
ctrl_step void ctrl_step(const CtrlInputs* in, CtrlOutputs* out) REQ Every control tick. Read in, write out. All pointers inside in (sensor_data, cam_pixels) are dead the instant you return — copy anything you keep.
ctrl_shutdown void ctrl_shutdown(void) REQ Once, before unload. Close logs, nothing else to free (you never malloc'd).
ctrl_get_debug_names const char* ctrl_get_debug_names(void) REQ Comma-separated labels for CtrlOutputs.debug[16]. The host auto-graphs each named channel live — your oscilloscope.
ctrl_configure void ctrl_configure(const SensorInfo* sensors, int count) OPT v2 Exactly once, right after ctrl_init: the car's sensor manifest. Pointer valid only during the call — copy it (that's what tt_car_configure is for). Without this export you get v1 behaviour: gyro/accel/wheel_vel only.
ctrl_get_vehicle int ctrl_get_vehicle(void) OPT v5 Called before the car exists (and before ctrl_init) — must answer from a constant. Return a CTRL_VEHICLE_* id to name the car this firmware wants, or CTRL_VEHICLE_MENU (0) to accept the menu's pick. Unknown/locked ids are reported on the console and the menu pick stands.

2.1Minimal complete controller

/* my_controller.c — the smallest firmware that drives. */
#include "tt_controller.h"

static TtCar g_car;

CTRL_EXPORT int ctrl_init(float hz) { TT_UNUSED(hz); return 0; }

CTRL_EXPORT void ctrl_configure(const SensorInfo* s, int n) {
    tt_car_configure(&g_car, s, n);   /* copy the manifest — the pointer dies */
}

CTRL_EXPORT void ctrl_step(const CtrlInputs* in, CtrlOutputs* out) {
    tt_drive(&g_car, out, 0.4f);       /* 40 % of each motor's max volts */
    tt_steer(out, 0.0f);              /* straight ahead */
    out->debug[0] = tt_speed(in);      /* graphed live in the sim */
}

CTRL_EXPORT void ctrl_shutdown(void) {}
CTRL_EXPORT const char* ctrl_get_debug_names(void) { return "speed_mps"; }

3.3SensorInfo — the manifest

One entry per configured sensor, in the same order its data appears in sensor_data. This is the whole point of ctrl_configure: cars are assembled from parts, so motor count, voltage limits, and sensor loadout are per-car facts your firmware is told, never facts it can assume.

FieldTypeMeaning
name[32]char[32]User-chosen sensor name (NUL-terminated) — as typed in the garage
typeintSENSOR_* tag (§4)
data_offsetintStart index into sensor_data
data_countintFloats this sensor contributes
range_min / range_maxfloatConfigured output range. For motors: ±maxVoltage. For a ToF: range_max is also the no-hit value.
actuator_indexintFor MOTOR: the actuator[] slot it reads. For LED: the first of its two slots. −1 for pure sensors (and unslotted LEDs).

§4Sensor catalog

All twelve SENSOR_* types. Every sensor is initialized the same way — bolt it onto the car in the garage (or receive it in a built-in design), give it a name, and it appears in the manifest handed to ctrl_configure. Firmware never initializes hardware; it discovers it.

Each card below gives the data slice layout, the extraction code, and a real-shaped sample. All samples assume tt_car_configure ran in ctrl_configure and car/in are in scope.

SENSOR_RF = 9IN · 10 floatsRF antenna — strongest-3 beacon pings · v6
layout[count, id0, rssi0_dbm, brg0_deg, id1, rssi1, brg1, id2, rssi2, brg2] slotsstrongest three pings, ordered by RSSI descending. Empty slot: id=−1, rssi=−100, brg=0. Three slots because trilateration needs exactly three references. bearingsigned yaw from the antenna's aim, degrees, + = right — steer toward a beacon by steering its bearing to zero fallofffree-space: rssi = tx_dbm − 20·log10(d), floored at −100 dBm; receive threshold −90 dBm. No occlusion, deliberately — triangulation stays solvable on a cluttered track. emitthe same part can transmit (garage: emit on, beacon id, tx power) — a car antenna is itself a trackable ping source for other cars. It never hears its own emission. 
int n = tt_rf_count(&g_car, in, "ant");            /* 0..3 heard this tick */
int s = tt_rf_find(&g_car, in, "ant", 4);          /* which slot is beacon 4? */
if (s >= 0) {
    float rssi = tt_rf_rssi(&g_car, in, "ant", s, -100.0f);
    float brg  = tt_rf_bearing(&g_car, in, "ant", s, 0.0f);
    float dist = powf(10.0f, (tx_dbm - rssi) / 20.0f);   /* invert the falloff */
}
sample · two beacons in range → [2,  4, −18.3, 12.5,  7, −26.1, −87.0,  −1, −100.0, 0.0]
SENSOR_MAG = 10IN · 1 floatmagnetometer / compass · v6
layout[heading_deg] — 0..360, 0 = world +Z, clockwise (a compass rose, not a math angle) initgarage: declination offset; noise model drift accumulates and wraps correctly across the 0/360 seam vs. gyrothe gyro gives you rate (drifts when integrated); the mag gives you absolute heading (noisy). Complementary-filter the pair.

layout[contact_01, force_N] — 1 while pressed this tick; peak contact force, 0 when untouched initgarage: mount point + activation radius (default 6 cm) + acceptance cone. Fires only for contacts near the mount and within the cone of its aim — a front bumper switch ignores a rear-end tap.

Noise is configurable, not free

Every sensor takes a per-part noise model in the garage (Gaussian noise, drift, quantization). Defaults are zero-noise and bit-deterministic — the same run replays identically. Turn realism on when your controller is ready to be lied to.

§5Actuator reference

Everything the firmware can do comes out through actuator[8] and debug[16].

ChannelSlotUnits / rangeSemantics
motor voltageper manifest (0..5)± maxVoltage (V)Signed; sign chooses direction. Host clamps to the motor's advertised limit. 0 V shorts the winding — that's drag braking, not coasting. A wheel with no motor free-rolls.
steering[6] CTRL_STEER_ACTUATOR−1 .. +1Front-wheel servo angle; + = right
brake[7] CTRL_BRAKE_ACTUATOR0 .. 1Friction brake, independent of motor voltage — you can brake and drive at once, and the car will not thank you for it
LED colouractuator_indexRGB24 as float(r<<16)|(g<<8)|b, integer-valued
LED blinkactuator_index + 1Hz, 0 = solid50 % duty, phased from deterministic sim time
debug graphsdebug[0..15]any floatAuto-graphed live under the names from ctrl_get_debug_names() — free instrumentation, use it constantly
Command latency

Actuator commands can ride a configurable transport delay (realism feature) — the same delayed array feeds motors and LEDs alike, so what you commanded this tick may reach the car a few ticks later, exactly like a real radio link.

§6Helper library — tt_controller.h

Header-only, every function static inline, no linking, no allocation. All of it is a readable wrapper over fields already in CtrlInputs/CtrlOutputs — ignoring it entirely is equally valid.

6.6Camera — kept frames (TtCamera ring)

The live buffer dies when ctrl_step returns, and the camera captures at ~10 Hz against a 100 Hz loop with no frame counter in the ABI. TtCamera is the fix: a static ring of the last TT_CAM_FRAMES (default 4) distinct frames as plain px[y][x] arrays — 16 KB per frame, ~64 KB static, no malloc anywhere (a freed buffer is a leak-per-Build&Reload waiting to be forgotten).

FunctionReturnsNotes
tt_cam_init(TtCamera* c)voidzero the ring; call from ctrl_init
tt_cam_update(TtCamera* c, const CtrlInputs* in)int1 only when a genuinely new frame was stored (byte-compared) — put your image processing behind this test and it runs 10×/s instead of 100. Sets c->oversize if a frame exceeds 128×128.
tt_cam_newest(const TtCamera* c)const TtFrame*newest kept frame, NULL before the first
tt_cam_frame(const TtCamera* c, int age)const TtFrame*frame by age (0 newest, 1 previous…), NULL when not held — the shape of every frame-diff
tt_cam_held(const TtCamera* c)intframes currently held, 0..TT_CAM_FRAMES

Honest edge

Two identical captures are indistinguishable from one: park facing a blank wall and the sequence number stops advancing. To know the camera is alive, watch in->time_s, not the ring.

§7Cookbook — worked firmware

Three complete controllers, each demonstrating a sensor family end-to-end. All compile against the two headers alone.

7.1Line follower — COLOR reflectance + PID

#include "tt_controller.h"

static TtCar g_car;
static TtPid g_steer_pid;

CTRL_EXPORT int ctrl_init(float hz) {
    TT_UNUSED(hz);
    tt_pid_init(&g_steer_pid, 3.0f, 0.2f, 0.08f);
    return 0;
}
CTRL_EXPORT void ctrl_configure(const SensorInfo* s, int n) {
    tt_car_configure(&g_car, s, n);
}

/* Two colour sensors aimed at the floor, one each side of the line
 * ("refl_l", "refl_r"). On the line both read bright; drifting right makes
 * the LEFT sensor go dark first. Steer to equalize them. */
CTRL_EXPORT void ctrl_step(const CtrlInputs* in, CtrlOutputs* out) {
    float l = tt_reflectance(&g_car, in, "refl_l", 0.5f);
    float r = tt_reflectance(&g_car, in, "refl_r", 0.5f);

    float err   = r - l;                       /* + = line is to the right  */
    float steer = tt_pid_update(&g_steer_pid, 0.0f, -err, in->dt_s);

    /* Slow down for sharp error — speed from confidence. */
    float effort = tt_lerp(0.55f, 0.20f, fabsf(err) * 2.0f);

    tt_steer(out, steer);
    tt_drive(&g_car, out, effort);
    tt_led(&g_car, out, "status",
           fabsf(err) > 0.3f ? 255 : 0, fabsf(err) > 0.3f ? 0 : 255, 0, 0.0f);

    out->debug[0] = err;
    out->debug[1] = steer;
    out->debug[2] = tt_speed(in);
}

CTRL_EXPORT void ctrl_shutdown(void) {}
CTRL_EXPORT const char* ctrl_get_debug_names(void) { return "line_err,steer,speed"; }

7.2Beacon homing with bump recovery — RF + BUMP + TOF

#include "tt_controller.h"

static TtCar g_car;
enum { SEEK, REVERSE, ARRIVED };
static int   g_state = SEEK;
static float g_state_t;

#define TARGET_BEACON 4
#define TX_DBM        0.0f     /* the beacon's tx power — you placed it   */

CTRL_EXPORT int  ctrl_init(float hz) { TT_UNUSED(hz); return 0; }
CTRL_EXPORT void ctrl_configure(const SensorInfo* s, int n) { tt_car_configure(&g_car, s, n); }

CTRL_EXPORT void ctrl_step(const CtrlInputs* in, CtrlOutputs* out) {
    int slot = tt_rf_find(&g_car, in, "ant", TARGET_BEACON);
    float rssi = tt_rf_rssi(&g_car, in, "ant", slot, -100.0f);
    float dist = powf(10.0f, (TX_DBM - rssi) / 20.0f);      /* metres */

    if (tt_bump(&g_car, in, "bumper") && g_state == SEEK) {
        g_state = REVERSE; g_state_t = in->time_s;          /* hit something */
    }

    switch (g_state) {
    case SEEK: {
        if (slot < 0) {                                     /* unheard: spin  */
            tt_steer(out, 1.0f);  tt_drive(&g_car, out, 0.18f);
            break;
        }
        float brg = tt_rf_bearing(&g_car, in, "ant", slot, 0.0f);
        tt_steer(out, tt_clamp1(brg / 35.0f));          /* steer brg → 0  */
        tt_drive(&g_car, out, dist > 2.0f ? 0.5f : 0.22f);
        if (dist < 0.6f) g_state = ARRIVED;
        break;
    }
    case REVERSE:                                           /* back out 0.8 s */
        tt_drive(&g_car, out, -0.3f);
        tt_steer(out, -0.6f);
        if (in->time_s - g_state_t > 0.8f) g_state = SEEK;
        break;
    case ARRIVED:
        tt_drive(&g_car, out, 0.0f);  tt_brake(out, 1.0f);
        tt_led(&g_car, out, "status", 0, 255, 0, 1.0f);  /* green blink */
        break;
    }

    out->debug[0] = dist;
    out->debug[1] = (float)g_state;
}

CTRL_EXPORT void ctrl_shutdown(void) {}
CTRL_EXPORT const char* ctrl_get_debug_names(void) { return "beacon_dist,state"; }

7.3Camera line follow with frame buffering — CAMERA + MAG

#include "tt_controller.h"

static TtCar    g_car;
static TtCamera g_cam;                 /* ~64 KB static ring, no malloc */
static float    g_balance;             /* held between camera frames    */

CTRL_EXPORT int ctrl_init(float hz) {
    TT_UNUSED(hz);
    tt_cam_init(&g_cam);
    return 0;
}
CTRL_EXPORT void ctrl_configure(const SensorInfo* s, int n) { tt_car_configure(&g_car, s, n); }

CTRL_EXPORT void ctrl_step(const CtrlInputs* in, CtrlOutputs* out) {
    /* Heavy image work only on ticks where a NEW frame arrived (~10 Hz). */
    if (tt_cam_update(&g_cam, in)) {
        g_balance = tt_cam_balance(in, 12);     /* bottom 12 rows = road  */

        const TtFrame* now  = tt_cam_newest(&g_cam);
        const TtFrame* prev = tt_cam_frame(&g_cam, 1);
        if (prev) {                              /* motion check by diff   */
            float d = tt_frame_mean(now, 0, 40, 63, 47)
                    - tt_frame_mean(prev, 0, 40, 63, 47);
            out->debug[2] = d;                   /* scene change per frame */
        }
    }

    /* Steering runs every tick from the held perception result. */
    tt_steer(out, tt_clamp1(g_balance * 3.0f)); /* chase the bright side */
    tt_drive(&g_car, out, 0.35f);

    out->debug[0] = g_balance;
    out->debug[1] = tt_cam_age(&g_cam, in);      /* 0..0.1 s: honest lag  */
}

CTRL_EXPORT void ctrl_shutdown(void) {}
CTRL_EXPORT const char* ctrl_get_debug_names(void) { return "balance,cam_age,frame_diff"; }

Drop the .c file in a UserScripts/ folder next to lib/tt_controller.h, build it as a DLL exporting the §2 symbols, and load it from the game's Simulate Controller screen. Build & Reload swaps your code while the car keeps existing — iterate live.

§8ABI version history

The ABI is append-only: every version keeps every earlier offset, so an old DLL loads and runs on a new host.
