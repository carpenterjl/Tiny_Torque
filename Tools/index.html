How the pieces fit together

Where vehicles live

A vehicle is one JSON file. The garage lists every file it finds in the Vehicles folder, so saving one there is all it takes to make it selectable in game.

Unity editor<repo>\UnitySim\Vehicles\
Installed build%USERPROFILE%\AppData\LocalLow\<company>\<product>\Vehicles\

On Chrome or Edge the Car Setup page can write there directly once you point it at the folder. Other browsers download the file and show you where to put it.

Where firmware lives

A controller is a folder of portable C plus one adapter file that speaks the ABI. Building it produces a DLL the game loads at run time:

  1. Drop the generated folder in Controllers\.
  2. Add its add_controller(...) line to Controllers\CMakeLists.txt.
  3. Run build.ps1 — the DLL lands in Assets\Plugins\x86_64\.
  4. Set controllerDll on your vehicle to that DLL's file name.

Building needs a 64-bit toolchain. If you have none, winget install --id BrechtSanders.WinLibs.POSIX.UCRT --exact installs one.

JGraph integration optional

If you have JGraph installed, every page that draws a plot can hand its data over for proper interactive figures and further analysis. The pages export a .m script plus a data.csv, and JGraph runs the script headlessly: 

jgraph -batch "speed_step.m" -showfigures -sd "C:\path\to\exported\folder"

For a live workflow, run the bridge script once. It watches a folder and opens any new script automatically, so clicking Open in JGraph on a page pops a figure window straight away: 

powershell -ExecutionPolicy Bypass -File Tools\jgraph-bridge.ps1

It finds jgraph.exe on PATH or in a JGraph source tree by itself; add -DryRun to check that without opening any windows, or -JGraph <path> to point it somewhere specific. The first time you click the button, pick the Tools\jgraph-out folder the bridge is watching — the browser remembers it after that.

Scripts are generated in MATLAB dialect rather than JGS on purpose: JGS's let requirement and index base are user settings, and a generated script must not depend on how a particular machine is configured. Without JGraph the pages plot everything themselves — nothing here is required.

Keeping these tools honest

The pages carry their own copy of the game's schema and physics constants, which means they can drift from the C# and the firmware headers. A regression test checks them against the real thing — a saved vehicle round-tripping without losing a field, the motor algebra reproducing MotorModel's closed forms, the derived plant constants landing on the values in mission_cfg.h: 

node Tools/verify.js

Run it after changing VehicleDesign.cs, MotorModel.cs, or the vehicle constants in mission_cfg.h, and update Tools/shared/ to match if it complains.
